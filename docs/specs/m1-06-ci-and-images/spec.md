## Solution

`.github/workflows/ci.yml` runs on every push:

| Job | What |
|---|---|
| checks | install, format, lint (incl. module boundaries), typecheck, unit tests, Paper & Pastel UI audit, build |
| integration | Testcontainers: Postgres 18 + pgvector, Valkey 8.1, the dev stack; includes the tenant isolation suite |
| browser | Vitest browser-mode component tests; Playwright E2E on Chromium, Firefox and WebKit, desktop and phone, light and dark, with axe and screenshots. Missing baselines (first Firefox/WebKit run) are written and uploaded as an artifact to review and commit; failures upload the report and traces |
| images | api, worker, web, admin built with BuildKit (GHA cache); pushed to `ghcr.io/<owner>/setubandh-<app>:<sha>` and `:main` on `main` only |
| deploy-staging | written but off until `vars.STAGING_ENABLED == 'true'` (Q-08); pulls images, migrates, rolling restart over SSH |

## Decisions

- **Compiled production code.** Workspace packages export TypeScript under the `@setubandh/source` condition (used by dev, tests, typecheck) and SWC-compiled `dist` under `default` (used in images). `.swcrc` keeps decorator metadata and writes full `.js` import paths. The condition is namespaced because Astryx publishes its own `source` exports.
- **Node image** (`infra/docker/node-app.Dockerfile`, `APP=api|worker`): Turborepo `prune --docker` → manifest-only install (cached) → build → a separate production-only install → runtime with `node:26-slim`, the compiled output and SQL migrations, running as the unprivileged `node` user, `HEALTHCHECK` on `/health/live` for the api, `STOPSIGNAL SIGTERM` (the apps exit 0 after closing). api 542 MB, worker 498 MB (about half is the Node base image).
- **Static image** (`infra/docker/static-app.Dockerfile`, `APP=web|admin`): Vite build served by Caddy on :8080 with SPA fallback, year-long caching for hashed assets, `no-cache` for everything else, `nosniff`, `X-Frame-Options DENY`. About 94 MB. TLS and public hostnames stay in the edge Caddy (§15.2).
- **Migrations in production:** `docker run … setubandh-api node /app/packages/db/dist/cli/migrate.js` (runs as `DATABASE_ADMIN_URL`; §15.4 "migrations first, then rolling restart").
- Node 26 images no longer ship corepack, so pnpm and turbo are installed with npm at pinned versions.
- Builds behind a TLS-inspecting proxy pass its CA as an optional BuildKit secret (`--secret id=extra_ca,...`). It is never stored in a layer and is absent in CI.

## Tests and verification

- **Acceptance "Pipeline green on main; images pushed":** verified when the workflow runs on GitHub (first run on this branch; images push once merged to `main`).
- Locally in the sandbox, every image was built and run:
  - The api passed its health check, answered `/health/ready` with both checks up, returned 404 for `/v1/docs` in production, and ran migrations from inside the image.
  - The worker started and stopped cleanly.
  - The web app served deep links with the right cache headers.
- The compiled api, worker and migration CLI were also run from `dist` with plain `node`.
- Playwright "missing baseline" mode was checked: a removed baseline is regenerated byte-identical and the test passes.
